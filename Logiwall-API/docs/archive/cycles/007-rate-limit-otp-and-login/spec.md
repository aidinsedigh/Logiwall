## Why this matters

Login is OTP-based. The code is 5 digits (90,000 possibilities) and valid for
2 minutes, and `ConfirmationOtpCode` accepts unlimited guesses with no
throttling, so a parallel brute force inside the validity window is realistic.
`SendOtpCode` is anonymous, sends a **paid SMS** and creates a user row for any
string, so anyone can burn SMS credit or flood the users table. There is no rate
limiting anywhere in the app (a grep for `AddRateLimiter` finds nothing). After
this plan:
- each OTP accepts at most 5 wrong guesses and is then invalidated;
- a phone number can request a new OTP at most once per 60 seconds;
- each IP gets a request budget on the anonymous auth endpoints;
- phone numbers must match the Iranian mobile format.

## Repo facts you need

- The git root is `D:\Own Projects\Logiwall`. Paths are relative to `Logiwall-API/`.
- .NET 8 ASP.NET Core. Its built-in rate limiter (`Microsoft.AspNetCore.RateLimiting`)
  is part of the shared framework, so no package is needed.
- Controllers are `partial`, with `[AutoInject]` fields. `IdentityController` is
  `[AllowAnonymous]`, with route `api/Identity/[action]`.
- The frontend (`Logiwall-Front/src/features/auth/api/otp.ts:66`) normalizes
  phone numbers to `0XXXXXXXXXX` (it replaces `+98` with `0`), so the server can
  require `^09\d{9}$`.
- **The frontend's OTP input expects 5 digits. Do not change the code length.**
- Services return `ServiceResponse<T>` (`Succuss` is misspelled on purpose and
  must not be renamed). Service-level failure messages in this codebase are
  plain English strings (e.g. `OrderService.cs:207` `"User is not registered"`),
  or `localizer.GetString(nameof(AppStrings.X))` for existing resource keys.
  **Do not add new `.resx` keys.** The `.Designer.cs` files are generated at
  design time and are not regenerated by `dotnet build`.
- `RestException` subclasses map to HTTP status codes in `ServerExceptionHandler`.
  `TooManyRequestsExceptions` (`src/Logiwall.Shared/Exceptions/TooManyRequestsExceptions.cs`)
  maps to 429.
- Test harness (from plan 005): `tests/Logiwall.IntegrationTests` uses
  `[Collection("api")]`, `ApiClient.LoginWithOtpAsync`, `ApiClient.NewPhone()`
  and `FakeSmsService.LastCodeFor(phone)`. Copy the structure of
  `tests/Logiwall.IntegrationTests/Identity/PasswordLoginTests.cs`.
