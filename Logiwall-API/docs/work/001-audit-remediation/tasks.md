## Product decisions surfaced by the plans

- **Archived or inactive accounts** cannot log in (plan 008 default). Confirm, or request "re-register archived numbers" as a feature.
- **Auth model**: OTP-only, or OTP plus password? The frontend calls `api/Person/ChangePassword`, which doesn't exist.
- **Blazor/MAUI clients**: keep them, or go API-only? This blocks the client side of the .NET 10 migration (016) and the template-DTO cleanup (015).
- **Frontend/API contract gaps**: the frontend calls `/api/Order/SelectPaymentType` and `/odata/Tipax/DspContractTrackings/...`, and neither exists. `use-query-orders.ts` calls the POST-only `GetOrders` with GET.

## Direction (not planned; options for the maintainer)

1. **Finish the payment loop** (partly covered by plan 012): a reconciliation job for stale `Pending` payments, refunds and cancellation, and aligning with the frontend's `SelectPaymentType`.
2. **Book and track shipments after payment**: `Order.ServiceProviderTrackingCode`, `PickupServiceId` and `PickupDateTime` are never set, and MyTipax only implements quoting. This needs a spike on the Tipax booking and tracking APIs.
3. **Choose one auth model**: going OTP-only removes `GetToken`'s password path entirely.
4. **Multi-carrier comparison**: after plan 011, adding a carrier is one class plus DI and seed rows. Parallel provider queries with per-provider timeouts would be the next step.

## Findings considered and rejected

- Missing `[Authorize]` on controllers: `MapControllers().RequireAuthorization()` applies globally, and only `Identity` and `Common` are anonymous, on purpose.
- OData over-exposure or `$expand` abuse: no endpoint uses `[EnableQuery]`. The pipeline is dead code and is removed in 015.
- HttpClient socket exhaustion: `HttpProvider` uses `IHttpClientFactory` correctly.
- `.Result` in `Shared/Extensions/TupleExtensions.cs`: it only runs after `Task.WhenAll`, so it's safe.
- Renaming `ServiceResponse.Succuss`: it is a wire contract with every client. Not worth it on its own.
- Full clean-architecture restructuring (moving logic into Application use-cases): high cost, no user-visible gain.
- Global `NoTracking`: update paths rely on tracking. Use targeted `AsNoTracking` instead (014).
- Migrating to .NET 9: support ends on the same date as .NET 8. Go straight to .NET 10 (016).
- `.idea/`, `*.DotSettings.user`, `Client.Core/node_modules`: all already gitignored and untracked.
- Changing the EF split-query default: Includes are single-level, so it does no harm.
